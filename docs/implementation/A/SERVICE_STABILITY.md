# 本机服务稳定性修复

日期：2026-11-06。主 Agent 维护。

## 问题与处理

本轮服务更新有两类中断：

1. V9 初次迁移使用了当前 MySQL 9.7 不支持的 MD5；随后未分类题库的迁移插入也触发外键失败。更新前已备份本机数据库；只移除失败 V9 新建的派生表与失败迁移记录，保留原账号、题目、作业和 V8。修正为每个出题者建立默认库，再关联未归类题目，事务检查确认旧题全部有题库映射后重新迁移成功。
2. 旧启动器直接运行 `backend/target` 下的构建文件。后续打包会替换运行中的文件，日志出现 TypeNotPresentException / ServletException；简单的 CSRF 接口仍可能返回200，不能代表登录和全部业务正常。

`backend/scripts/run-demo.py` 现先将构建产物复制到私有 runtime 目录，以 SHA-256 命名并设只读，再启动 JVM。后续构建不修改该运行副本。`scripts/local_app.py` 同时识别旧路径和新运行副本，仍只管理本项目进程，不停止其他系统服务。

## 环境边界

访问入口为 `http://192.168.2.100/`，systemd socket将80转发到前端5173，前端 `/api` 再代理到回环8080。未增加 HTTPS，后端/数据库/评测服务没有对局域网开放。

这是当前开发机的修复与实测；未将其视为正式 MariaDB / Rocky Linux 8 部署验收。历史错误日志保留，判断当前状态应查看最新进程与最新时间。
