# 用户、名单、题库、作业与讨论管理交接

日期：2026-11-06（Asia/Shanghai）。实现：主 Agent；独立复核：management_qa。阶段：本机真实服务联调及旧入口自动归库修复验证通过；正式 MariaDB / Rocky Linux 8 未验收。

## 用户确认与当前范围

- 学生名单支持 Easy Parse；未知学生自动创建 STUDENT 账号并加入所选班级。导入者填写统一初始密码，已有账号密码和资料不变。
- 管理员可手动创建 STUDENT / TEACHER / ADMIN，可修改所有账号的姓名、学生学号、昵称、简介、AI 偏好与头像。编辑入口不修改登录名、角色和密码。
- 题目管理按“题库 → 题目 → 编辑”组织；发布作业可选择全量、统一随机或每人随机。
- 发布时分别决定是否允许 AI 辅助和题目讨论；教师和管理员可撤回消息、禁言学生，也可从被禁言列表解禁。
- 最新界面要求：AI 按钮仍在代码编辑器附近，回复放左侧青色栏的对话框；选择 TINO 时形象放在对话框下方。覆盖此前把 AI 按钮也移至侧栏的理解，前端 Agent 负责交付。

## 已实现行为

### 用户管理

后端 `identity/UserManagementController.java` / `UserManagementService.java`，前端 `UsersView.vue`。所有接口都在服务端检查 ADMIN，学生或教师不能通过构造请求访问。

创建时校验登录名唯一、学号唯一、角色和密码规则。登录名为 3–100 位 ASCII 字母、数字、下划线、点或连字符，首位必须为字母或数字。密码至少 8 字符、包含字母和数字，最多 72 个 UTF-8 字节；仅保存 BCrypt。学号仅适用于学生，允许为空；非空为 1–32 位字母、数字、下划线或连字符，首位必须为字母或数字。

姓名为 1–100 个 Unicode code point；昵称最多 32、简介最多 500。学校姓名与昵称分开维护。头像沿用本人设置的实际 PNG/JPEG 检测、512 KiB 上传限制、单边 4096 像素限制、缩放及 PNG 重编码。管理员头像读取路径需管理员身份，响应禁止共享缓存；不接受任意远程头像 URL。

TINO 解锁与有效风格规则见 [TINO 交接](../C/TINO.md)。管理员编辑也不能替尚未解锁的账号直接启用 TINO。

### 班级名单 Easy Parse

后端 `roster`，前端 `StudentImportDialog.vue` / `ClassesView.vue`。教师只能导入自己的班级，管理员可管理全部班级；预览和校验都不创建账号。

支持粘贴文本和 TXT / CSV / TSV / XLSX / DOCX。文本上限 1 MiB，文件上限 5 MiB，每次最多 200 名学生。支持常见表头别名、分隔符、表头前的标题和 CSV 引号；识别结果可修改、选择，再重新校验。不是任意材料无条件识别，不支持旧版 XLS / DOC、PDF 或扫描件 OCR。

XLSX 限一个工作表、最多 1000 行和 50 列，拒绝公式，保留可识别的学号格式与真实行号。DOCX 读取表格和段落。压缩文件限制最多 256 个条目、累计解压 8 MiB；名单解析不调用外部 AI。

按学号匹配已有账号，同时核对姓名及明确提供的登录名；只接受启用的 STUDENT。班级名若填写，必须与所选班级一致。新账号未指定登录名时使用学号，并执行登录名规则。已有账号的实际登录名在预览中显示，不从登录名猜测学号。

确认导入再次检查权限、全部行和冲突；事务内新增账号及成员关系。任何错误导致整批回滚。重复确认由 `Idempotency-Key` 回执保护：同键同内容返回原结果，同键换内容或密码返回 409；新键再次导入已有成员返回 unchanged，不修改密码、昵称、头像或权限。回执仅保存初始密码的 BCrypt 比较摘要，不保存明文。

### 题库与作业

后端 `ProblemLibraryService` / `TeachingService`，前端 `LibrariesView.vue` / `ProblemsView.vue` / `TeacherAssignmentsView.vue`。

题库成员指向题目，显示其最新版本；发布作业时另建固定版本快照。编辑题库中的题目不会改动已发布作业。教师仅管理自己的题库和题目；管理员管理全部，但不能把不同拥有者的题目混入同一题库。

题目 Easy Parse 保存草稿时同步建立题库；返回的 `problemSetId` 与新题库 ID 相同，原导入响应兼容。V9 已把原有题目映射到题库，原作业快照保留。

独立复核发现旧 `POST /api/teacher/problems` 会新建未归库题目；已改由 `saveUncategorized` 在事务内创建/锁定拥有者的“未分类题目”库，再保存与关联题目。默认 ID 沿用 V9 的拥有者 ID 去连字符规则，已存在库的标题保留。旧接口仍返回 201，新题库内创建路径不额外挂默认库。该修复已经主 Agent 统一构建部署，并通过两次并发创建与权限隔离的真实 HTTP 验证。

| 出题方式 | 发布行为 | 学生视图 |
| --- | --- | --- |
| FULL（全量） | 固定全部候选题目版本 | 全班同一完整题序 |
| SHARED_RANDOM（统一随机） | 从候选池无放回抽取指定数量，发布时固定 | 全班同一抽题结果 |
| PER_STUDENT_RANDOM（每人随机） | 固定候选池；学生与抽题结果持久绑定 | 每名学生只见自己的固定题目及顺序 |

每人随机要求候选题分值相同，保证总分一致。晚入班学生首次访问时在作业锁内生成绑定，并发访问保持同一结果。学生未抽中的题目不能通过详情、提交、AI 或聊天室路径访问。学生响应不暴露其他候选题目或完整题池数量。

`aiEnabled` / `chatEnabled` 在发布时设置，后端独立执行检查；仅隐藏按钮不能替代权限。旧作业迁移为 FULL、AI 开启、讨论关闭。后续已补发布后五参数修改，见 [作业编辑](ASSIGNMENT_EDIT.md)。

### 题目讨论与禁言管理

后端 `chat`，前端 `ProblemChat.vue` / `ChatManagementView.vue`。聊天室按作业及固定题目版本隔离。前端每 3 秒轮询最近 50 条，纯文本显示消息；当前没有更早历史的翻页界面。

消息去除首尾空白后为 1–1000 个 Unicode code point。发送需要幂等键；同作者同键同内容返回原消息，变更内容返回 409。每位作者跨聊天室至少间隔 2 秒；作者行锁、当前读和唯一约束约束并发写入。

教师只能管理自己的作业；管理员可管理全部。撤回为软删除，学生响应中原正文立即变为空字符串，保留“已撤回”状态。学生不能调用教师撤回接口。

禁言范围是整份作业的全部题目，不能切题绕过。只能禁言该作业班级中的学生；被禁言学生可读讨论但不能发言。被禁言列表仅管理者可见，解禁为幂等删除；发送与禁言操作锁定同一学生记录，避免禁言完成后并发发送绕过。关闭讨论后学生无法读取/发送，教师仍可读取与管理历史；所有角色均不能在关闭的讨论中发新消息。

| 迁移 | 内容 | 本机状态 |

V9 首次执行遇到本机 MySQL 9.7 的 MD5 不可用，随后又遇到同事务插入查询未取得默认库行导致外键失败。最终改成先为各题目拥有者创建默认库，再关联未归库题目；主 Agent 已核对原题全部可达并成功迁移。修复只清理失败 V9 的新派生表与失败记录，未删除原业务数据。更新前备份位于私有 `.local/before-management-20261106-224616.sql`，不向网页或交接复制数据内容。

本轮真实 HTTP 入口为局域网 HTTP 80，同源代理到回环后端；本机数据库为 MySQL，不是 MariaDB。后端改用独立运行时 JAR，避免构建替换正在运行的包。部署、恢复和总状态由主 Agent 在项目 README、NEXT_SESSION、RUN_STATUS 维护，本文件不管理进程。

`management_demo.py` 每次运行会创建一套新的合成资料，不应用作无条件健康检查。已有记录在私有 `.local/management-check.json`。`management_followup.py` 默认只使用这套资料，不创建账号或作业，不调用 AI；重复导入会留下正常幂等回执，临时头像有恢复检查。显式 `--check-legacy-create` 首次额外创建两道合成草稿并保存 ID，之后复用。复核时未修改真实学生昵称、头像或密码，未读取、输出或调用 AI 密钥。

## 限制与下一步

- 正式 MariaDB、Rocky Linux 8、生产 JDK 21 和正式学校 AI 仍需目标环境验收；本机通过不能替代。
- 当前每次发布最多 100 道候选题；发布页面题库/班级选择各读取前 100 项，尚无跨页检索选择。题库管理本身已有分页。
- 尚无管理员修改既有登录名/角色、密码重置、题库删除/转移或更早聊天记录的界面。
- 已有并发验证覆盖导入同键和晚入班抽题；全服务容量、跨进程故障注入、所有事务交错未系统压测。
- 旧入口自动归库修复已经统一部署并完成验证。原合成资料增加 `legacyProblemIds` 保存本次两道草稿，之后复核复用这些 ID；本 Agent 未重启服务或打包运行产物。
