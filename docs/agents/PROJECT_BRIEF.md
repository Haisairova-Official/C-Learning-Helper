# 项目共识

## 目标

实现一个参考 PTA 教学流程的 C 语言教学辅助系统，服务教师布置作业、学生在线编程、服务器自动评测和学校 AI 排错指导。

## 用户明确提出的需求

- 教师提供题干、参考答案、预期输入输出和测试用例。
- 学生通过网页提交 C 代码，服务器编译、执行测试用例并返回结果。
- AI 读取题干、参考答案、限制提示词和学生当前代码，提供排错指导。
- AI 不得直接透露参考答案或给出完整解答；提示词约束的效果必须验证，不能承诺绝对防泄露。
- 使用 MariaDB。
- 预期部署在一台 Rocky Linux 8 服务器上，采用原生部署；保留对学生代码的隔离和资源限制。
- 参考 PTA 的题目集、作答和教学管理流程。
- 有题目管理权限的教职工和管理员能够使用 Easy Parse 快捷导入题目集，兼容常见的非严格模板格式。
- 多 Agent 分工开发，主要通过 Markdown 传递需求、接口、进度与交接信息。

| 层次 | 选择 |

## 第一版实现基线

以下是为并行开发整理的默认方案，可依据老师要求调整：

- 角色：学生、教师、管理员。教师管理自己的班级和题目，管理员具备管理与批量导入权限；接口逐项检查对象归属。
- 题目类型：完整 C 程序题，以标准输入输出评测。
- 教学组织：题库中的题目组成题目集/作业，作业发布给班级并设置开放与截止时间。
- 评测：异步任务、逐测试点结果、部分分、保留每次提交。日常作业取截止前受理的提交中的最高得分；最终判分可以在截止后完成。
- AI：学生主动请求分析当前编辑代码；即使未提交评测，也可以发送当前代码。分析记录绑定代码快照，避免与之后修改的代码混淆。
- Easy Parse：优先支持粘贴文本、TXT、DOCX；采用规则识别与可修正预览。导入先保存为草稿，再通过发布校验。
- 页面：作业列表、题目与编辑器、结果与历史、AI 指导、教师题库作业管理、导入预览、基础成绩统计。
- 交互：评测结果先采用轮询。AI 第一版在完整响应校验后展示，便于落实输出约束。
- 任务调度：MariaDB 任务记录配合有限并发工作线程，支持任务领取、超时和恢复。

## 数据边界

- 学生接口只返回公开题目内容、公开样例、自己的提交和允许查看的结果。
- 参考答案和隐藏用例由服务器按权限读取，不能依赖前端隐藏字段实现保密。
- 隐藏测试点仅返回状态、耗时、内存和允许公开的得分，不返回原始输入、期望输出或可反推输入的程序输出。
- AI 把参考答案作为参考，不应将学生采用不同的正确算法判定为错误；评测结果由确定性的执行与比对模块给出。
- 限制提示词由后端控制。学生代码及其注释作为待分析数据处理。
- 导入文件中的答案、解析和教师备注需要单独归类；归属不明时阻止自动公开该段内容，提示教师确认。
- 日志避免记录完整参考答案、隐藏用例和密钥；原始导入材料只对具备权限的人员开放。

## 范围控制

第二阶段候选：函数题、PDF 与扫描件 OCR、多文件题、更复杂输出校验、查重、监考、实时消息推送。它们尚未纳入第一版交付。

第一版围绕一个后端工程和一个前端工程构建；go-judge 作为本机独立服务运行。数据库任务表支撑当前规模，按后续实测决定是否增加组件。
