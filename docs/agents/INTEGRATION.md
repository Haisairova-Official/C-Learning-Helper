## 第二阶段：最小业务流程

- [x] 教师通过 Easy Parse 导入含参考答案和样例的材料，预览修正后生成草稿。
- [x] 教师补齐并确认测试用例、分值和限制，将题目集发布给指定班级。
- [x] 学生只能查看自己可访问的作业，能编辑并提交 C 代码。
- [x] 提交立即得到记录编号，最终返回真实编译和用例结果。
- [ ] 学生请求分析当前代码，系统传入匹配版本的题干、参考答案及服务端限制提示词，返回指导。
- [x] 上述 AI 入口已验证授权、输入快照和显式模拟响应；真实学校指导质量尚未验收。
- [x] 教师查看班级完成情况和成绩，学生查看自己的历史记录。

## 第三阶段：关键异常与边界

- [x] 评测覆盖：正确、部分正确、编译失败、运行崩溃、死循环、内存超限、输出超限。
- [ ] 受控验证学生进程不能访问业务敏感文件、网络及其他提交的工作文件；验证后清理测试数据。
- [x] 已单独验证宿主专用 canary 的读/写/删除、shell 写入、有限 fork 与单个本机临时端口连接受限，无残留测试进程。未直接操作真实敏感文件，也未将所有跨提交隔离情形标为已测。
- [x] 评测基础设施错误记为系统异常，score 为 NULL，不误判成学生零分。
- [x] 幂等请求、旧租约拒绝、过期任务恢复及冷重启数据保留通过；不代表已完成所有进程故障注入。
- [ ] 作业截止判定依据服务端受理时间，已受理任务可在截止后完成。
- [x] 题目发布后的编辑不改变已有作业和历史提交的版本依据。
- [x] 学生通过修改 ID 不能查看他人提交；不可访问的题目版本被拒绝；学生题目视图不包含参考答案或隐藏用例。
- [ ] AI 覆盖不同正确解法、诱导泄露的代码注释、过长代码、超时、接口失败、无效响应。
- [x] AI 分析绑定当前代码快照，前端能识别编辑后结果对应旧版本。
- [x] Easy Parse 常见标题/题号及 C 代码保留规则、DOCX 文本/表格读取有测试；复杂真实教师材料仍待扩大覆盖。
- [x] 解析不确定时提示修正，测试中的答案不归入公开题干；重复确认不产生重复题目。启发式解析仍要求教师复核。
- [x] 上传大小、文件类型和解压规模受限，原文件不落盘，提取材料受对象权限保护；恶意 DOCX 外部实体和解压超限被拒绝。
